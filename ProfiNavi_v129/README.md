# ProfiNavi v138 stable clean R2

v138 — стабильная версия после полного регрессионного прохода и перехода на чистое состояние базы.

## Перед первой публикацией v138

В Supabase нужно **один раз** выполнить:

`profinavi_v138_clean_reset.sql`

Этот файл:

- удаляет все старые тестовые данные ProfiNavi из `public`-таблиц;
- сохраняет сам Supabase-проект, API keys, Edge Functions и Storage buckets;
- сохраняет закрытый `profinavi_admin_allowlist`;
- приводит booking/calendar/chat backend к финальной схеме v138;
- добавляет `schedule_enabled`;
- защищает от пересекающихся записей на уровне PostgreSQL;
- резервирует весь диапазон длинной услуги;
- корректно освобождает только те окна, которые всё ещё входят в актуальный график мастера;
- закрывает booking-chat после `cancelled/declined`;
- перезапускает публичные ID мастеров с `1`.

Auth identities на сервере специально не удаляются SQL-скриптом: Auth — отдельная системная подсистема Supabase. При первом запуске v138 frontend один раз очищает старую локальную сессию и пользовательские кэши, поэтому браузер начинает с экрана входа. Старые Auth-пользователи без `public.profiles` не содержат бизнес-данных и могут безопасно войти/зарегистрироваться заново.

Старые Storage-файлы также не удаляются SQL напрямую (Storage управляется отдельным API); после очистки базы на них больше нет ссылок, поэтому в ProfiNavi они не отображаются.

## Основные исправления v138

- безопасная загрузка `client.html` при существующих записях;
- booking-flow сохраняет мастера/услугу/дату/время через login/registration;
- booking использует реальный `service_id`, серверную цену и длительность;
- календарь проверяет непрерывную доступность на всю длительность услуги;
- клиент может отменить запись; мастер — подтвердить, отклонить и завершить;
- клиентские и мастерские чаты восстанавливаются из Supabase на другом устройстве;
- чат закрывается после `cancelled/declined` и после окна общения;
- избранное синхронизируется с аккаунтом;
- техническая поддержка клиента/мастера и inbox администратора входят в общий chat-flow;
- расписание не удаляет занятые slot rows;
- `schedule_enabled` отделён от фактической занятости;
- индивидуальные рабочие дни сохраняются после backend hydration и редактирования администратором;
- карта: исправлены «На этой неделе», фильтр цены и реальная услуга;
- аналитика использует фактическую цену booking;
- отзыв доступен после окончания услуги;
- усилено HTML-экранирование пользовательских данных;
- безопасные return-path после client/master/admin login;
- Service Worker: `profinavi-v138-stable`;
- при первом запуске stable один раз очищаются старые v129–v137 локальные test/session caches.
